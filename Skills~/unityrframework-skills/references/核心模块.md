# 核心模块选型与使用

## 阅读方式

按模块查“适用/不适用、流程、最小业务模式、生命周期、查询”。这里的调用名是检索入口，不是全部重载；生成代码前仍需按 [API 查询](API查询.md) 核对当前版本。示例地址都应由项目提供，不能照抄成全局常量。

除 Framework、Log、基础安全外，Runtime 入口通常在 `Scripts/Runtime/<模块名>/<模块名>Component.cs`；Library 契约在 `Library/RFramework/RFramework/<模块名>/I<模块名>Module.cs`。路径相对当前核心包根目录，不相对技能安装目录。

所有业务都在框架就绪后访问模块。框架就绪不代表资源已初始化、配置已加载或语言已准备好；按业务依赖顺序等待。

## Framework

- **适用/不适用**：应用级帧率、逻辑时间缩放、暂停、后台运行、启动/关闭/软重启；不是玩家进度或业务状态容器。
- **流程**：复用启动场景的框架根节点；确认 Controller 与模块已初始化，再使用 `GameEntry.Framework`。需要退出或软重启时调用 `GameEntry.Quit()` / `GameEntry.Restart()`。
- **最小业务模式**：暂停菜单使用 `PauseGame()` / `ResumeGame()`；重启前按业务需要完成保存和收尾，不在每个场景新建根节点。
- **生命周期/误用**：软重启会清除组件缓存、关闭模块并重载 0 号场景，不是重新启动操作系统进程；不要保留跨重启的静态业务引用或用软重启替换已加载热更 DLL。
- **查询**：`Scripts/Runtime/GameEntry.cs`、`Scripts/Runtime/Base/UnityRFrameworkController.cs`、`Scripts/Runtime/Base/UnityRFrameworkRuntime.cs`；示例看 `Sample.Demo` 的启动与返回流程。

## Log

- **适用/不适用**：业务诊断与错误上下文；不是独立 GameEntry 模块，也不是遥测上传服务。
- **流程**：使用 Runtime 的 `Log.Info/Warning/Error`；需要平台日志策略时核对 Controller 的 `ILogHelper`，不要逐处改业务调用。
- **最小业务模式**：输出加载失败的 location、阶段和异常，但不记录密钥、密码或令牌。
- **生命周期/误用**：Runtime 安全日志在启动前或停止后会忽略迟到写入；默认 Helper 会落盘，项目不允许落盘时须由项目配置其策略。
- **查询**：`Scripts/Runtime/Utility/Log.cs`、`Library/RFramework/RFramework/Base/Log/ILogHelper.cs`；定位 `DefaultLogHelper` 查看落盘行为。

## Setting

- **适用/不适用**：音量、语言、分辨率、显示偏好等少量非敏感键值；不用它存玩家进度、大对象、密码或令牌。
- **流程**：启动读取带默认值的 `GetBool/GetInt/GetFloat/GetString`，由业务应用；改变设置时 `Set*`，在合适时机 `Save()`。
- **最小业务模式**：滑块改变 Audio 音量并保存 Setting；下次启动先读 Setting，再赋值 Audio；语言设置先确认语言切换成功再保存。
- **生命周期/误用**：默认 PlayerPrefs 不加密；框架停止、软重启和应用暂停有待写入保存，但重要交互可显式保存，不要每帧写盘。Setting 不会自动改变音量或显示。
- **查询**：`SettingComponent.cs`、`ISettingModule.cs`、`DefaultSettingHelper`；示例看 `Sample.Demo/Scripts/Runtime/Hall/DemoTopBar.cs` 和启动流程。

## Storage

- **适用/不适用**：可序列化进度快照、多个手动槽位、自动存档、压缩、备份与可选认证；不是静态配置或普通音量设置。
- **流程**：业务创建独立数据快照，`SaveAsync` 后检查 `Succeeded/Reason/Message`；`LoadAsync<T>` 成功才应用 `Data`，同时识别 `RecoveredFromBackup`。
- **最小业务模式**：手动保存使用项目槽位名；重大选择、结算或换图时用 `SaveAutoAsync(data)`，读取使用 `StorageSlotNames.AutoSave`。普通 `SaveAsync` 不得覆盖自动槽位。
- **生命周期/误用**：备份是上一版有效数据，不保证等于最近一次主存档；读取失败不能直接覆盖旧存档。取消或异常与结果失败都须处理；不要传正在变化的场景对象代替数据快照。
- **查询**：`StorageComponent.cs`、`IStorageModule.cs`、`StorageOptions.cs`、`StorageSlotNames.cs` 与序列化器；`Sample.Storage` 展示槽位、压缩、认证、恢复和重启。
- **可选保护**：未提供 options 时使用 Inspector 默认值；安装级 SaveKey 与 ConfigKey/YooAssetKey 无关。清数据、卸载或密钥丢失可能导致旧存档无法解密；跨设备同步需项目另设计，不默认开启。

## Config

- **适用/不适用**：发布的静态规则和数据表；不用于保存玩家运行时进度。
- **流程**：使用当前 CSV/Excel 工具生成行类型与产物；核对 Json/Binary Helper、单表/多表容器、保护模式及 Resource 地址；完成加载后 `GetConfig<T>(id)` 或 `GetAllConfigs<T>()`。
- **最小业务模式**：启动预加载角色或设备参数表；实例化业务对象时按 Id 读取；要修改的是业务状态，不要把配置行对象当作共享可变玩家数据。
- **生命周期/误用**：重复加载同一行类型会替换表，不是增量追加；Bundle 按其契约解析并提交；自定义 Codec 必须在读取前注册。别把任意 JSON 数组或 JsonUtility 输出当作生成器的现行格式，也别凭 .bytes 后缀猜解析器。
- **查询**：`ConfigComponent.cs`、`IConfigModule.cs`、`JsonConfigHelper`、`BinaryConfigHelper`、`Scripts/Editor/ConfigPipeline/`；`Sample.Demo` 的 `DemoDataLoader` 和生成配置代码。
- **可选保护**：ConfigComponent 保护模式与导出须一致，固定 Resources ConfigKey 自动加载；已有密钥升级时复用。Config 加密与资源 Bundle 加密可叠加但不是同一层。

## Localization

- **适用/不适用**：语言表、静态 UI 文案、带占位符的动态文字；不是通用 JSON 存储。
- **流程**：导出实际语言产物，检查 Helper 与 location，等待 `SwitchLanguageAsync`；静态 Text/TMP 使用 `LocalizedText`，动态文案由业务 `GetString(key, args)` 生成。
- **最小业务模式**：设置界面切换语言成功后保存 Setting；启动读取上次语言，并在需要文本的界面首次展示前完成语言准备。
- **生命周期/误用**：预载多语言 Bundle 不等于切换当前语言；同步 `SwitchLanguage` 只切已加载语言。语言标识以项目现有表为准；未实现位置提供器的自定义 Helper 需要显式 location。
- **查询**：`LocalizationComponent.cs`、`ILocalizationModule.cs`、`LocalizedText`、`ILocalizationLocationProvider`；`Sample.Demo` 的启动流程和 `DemoTopBar`。
- **UGUI/TMP**：普通 UI 默认使用 UGUI；项目已有或明确指定 TMP 时兼容它，并检查业务 asmdef 对 `Unity.TextMeshPro` 的引用，不能只补 `using TMPro`。

## Resource

- **适用/不适用**：加载并归还资产、提供上层模块的数据来源；是否支持远端更新由 Helper 决定，默认 Resources 不提供版本下载。
- **流程**：检查 ResourceComponent 的 Helper、模式、包名与服务器；复用项目已有的 `InitializeAsync` 链路，不在每个使用者重复初始化。用当前 Helper 可解析的 location 加载。
- **最小业务模式**：直接 `LoadAssetAsync<T>` 获取的每次成功引用，在用途结束时对应一次 `UnloadAsset<T>(location)`；自己 Instantiate 的对象也由自己销毁，在实例仍依赖资产时不要提前归还。
- **生命周期/误用**：缓存或并发去重不免除每个调用者的归还义务；`UnloadUnusedAssets` 不能替代引用归还。迟到成功也要清理，取消不能假定所有底层加载立即停止。
- **查询**：`ResourceComponent.cs`、`IResourceModule.cs`、实际 `ResourceHelperBase` 子类；本地使用 `Sample.Demo`，远端使用 YooAsset Demo。
- **地址规则**：Resources 使用相对 Resources 的地址；LocalFile 使用安全相对文件路径和扩展名，优先 persistentDataPath、再 StreamingAssets、再默认实现；YooAsset 使用实际 Package 的 Address/location。Android/WebGL 的 StreamingAssets 不应直接当普通文件用 File.ReadAllBytes 读取。

## UI

- **适用/不适用**：统一管理窗口打开、关闭、层级、全屏遮挡、返回栈及场景 UI；不规定业务采用什么架构，也不是自动绑定或红点系统。
- **流程**：框架创建的 Prefab 用 `OpenUIFormAsync` / `CloseUIForm`，业务行为可继承 `UIFormLogic`，通过 userData 传项目参数；场景已有对象用 Binder 或 Register/Unregister。
- **最小业务模式**：打开设置窗口，在打开生命周期绑定事件、填充数据；关闭时取消任务、解绑监听；弹窗关闭不另写一个与框架栈不同步的 Destroy 流程。
- **生命周期/误用**：框架创建的 UI 由模块销毁并归还引用，别重复手动 Unload；场景 UI 由场景/外部持有，注销不会替外部销毁。同地址不能重复打开；UI 当前不使用对象池。
- **查询**：`UIComponent.cs`、`IUIModule.cs`、`UIFormLogic.cs`、`SceneUIFormBinder.cs`；`Sample.UI` 及需要的 `Expansion.UI.Demo`。
- **布局边界**：普通 Prefab 放框架 Canvas 的层级；独立 Canvas 保留自己的 Camera、Scaler、Sorting 等设置，逻辑层级不保证独立 Canvas 的实际渲染顺序。场景 UI 跨场景存活需明确归属持久化根；检查单个有效 EventSystem 和匹配的 Input Module。

## Entity

- **适用/不适用**：需要实体编号、分组、显示/隐藏、生命周期和父子附加的角色或模型；不是每个临时 class 或所有 GameObject 都必须接入。
- **流程**：先建立/确认实体组，使用唯一 Id 和地址 `ShowEntityAsync`；行为放 `EntityLogic`；不用时 `HideEntity`；已在场景中的对象用 SceneEntityBinder 或 Register/Unregister。
- **最小业务模式**：创建角色实体后创建武器实体，按 Id `AttachEntity`；隐藏/再次显示时重置上一次的业务状态。
- **生命周期/误用**：Entity 自己维护资源地址与实例缓存，不再套一层通用 Pool；组容量不是每种 Prefab 独立容量。场景实体注销/关闭不由模块销毁，也不进入其实例缓存。
- **查询**：`EntityComponent.cs`、`IEntityModule.cs`、`EntityLogic.cs`、`SceneEntityBinder.cs`；`Sample.Demo` 的远征与实体行为代码。

## Pool

- **适用/不适用**：反复创建/回收的普通 class 或项目自己持有的 GameObject；不是资源下载缓存，也不用于重复包装 UI/Entity 的生命周期。
- **流程**：按使用者生命周期创建具名池，配置创建、Spawn/Unspawn 清理回调；用 `Spawn` 取得，用 `Unspawn` 归还；不再需要池时由其所有者销毁。
- **最小业务模式**：自己管理的高频特效使用 GameObject 池；新一轮 Spawn 重置计时、位置和业务引用，Unspawn 取消旧任务和监听。
- **生命周期/误用**：不要把同一对象重复归还或直接 Destroy 后再归还；池管理实例不等于替你持有 Prefab 资源，源资产须活到所有依赖实例释放。
- **查询**：`PoolComponent.cs`、`IPoolModule.cs`、`IObjectPool<T>`；检索当前项目 `CreatePool` / `CreateGameObjectPool` 的使用者。

## Event

- **适用/不适用**：一对多业务通知，如进度或语言状态变化；需要立即返回结果的一对一操作通常直接调用业务方法，不把所有调用转成事件。
- **流程**：定义项目自己的强类型消息，Subscribe 后 Fire；用 `EventGroup` 或成对 Unsubscribe 管理订阅范围。
- **最小业务模式**：数据变化由业务发布消息，已打开界面订阅并刷新；界面关闭时 Dispose 订阅组，重新打开才重新订阅。
- **生命周期/误用**：匿名委托需要保存同一个引用才能解绑；重复打开不能叠加监听。Fire 是同步分发，FireAsync 是线程安全入队并在主线程分发，不代表所有模块都线程安全。
- **查询**：`EventComponent.cs`、`IEventModule.cs`、`EventGroup.cs`；Demo 的事件定义与 UI 订阅。

## Timer

- **适用/不适用**：框架驱动的延迟、周期任务、倒计时；不用于等待网络或资源 Task 完成，也不是永久系统时钟。
- **流程**：`RFramework.Timer.CreateOnce/CreateRepeat` 创建句柄，当前 Runtime 使用 `GameEntry.Timer.RegisterTimer` 注册；业务保存句柄，需要时 Pause/Resume/Cancel。
- **最小业务模式**：界面自动关闭计时器在打开时创建，提前关闭时 Cancel；创建时明确 `ignorTimescale` 是否忽略逻辑时间缩放。
- **生命周期/误用**：只创建未注册不会运行；不要凭旧示例猜方法叫 Register。业务不能为取消一个定时器调用 `CancelAllTimers` 影响其他使用者。
- **查询**：`TimerComponent.cs`、`ITimerModule.cs`、`Timer.cs`；按当前源码核对重载及默认时间缩放参数。

## Fsm

- **适用/不适用**：角色、设备或交互对象的局部状态机；不自动替代应用级 Procedure 或业务架构。
- **流程**：实现 `IFsmState` / `FsmStateBase`，用拥有者对象和状态实例 `CreateFsm`，保存返回的 IFsm；核对初始状态策略后 ChangeState，不用时 DestroyFsm。
- **最小业务模式**：设备待机、运行、故障状态，状态持有自己的计时器和任务，在离开时清理。
- **生命周期/误用**：CreateFsm 首参是 owner 而不是字符串名称，DestroyFsm 传实例。回调是同步 void，不改成 async void；异步任务的收尾见业务脚本规范。
- **查询**：`FsmComponent.cs`、`IFsmModule.cs`、`IFsm.cs`、`FsmStateBase.cs`。

## Procedure

- **适用/不适用**：启动、初始化、登录、大厅、业务场景与返回等应用级流程；不用于所有角色的 AI 状态，也不强制整个项目必须状态机化。
- **流程**：派生 `ProcedureStateBase`；显式 Initialize 或 InitializeFromAssembly 后 StartProcedure；流程完成后 ChangeProcedure；在离开和关闭时取消其任务。
- **最小业务模式**：启动流程等待资源初始化、配置和已保存语言准备好，再加载界面/场景进入下一流程；不要让每个 UI 自己再初始化资源。
- **生命周期/误用**：自动发现只扫描指定业务程序集，状态需公共无参构造函数，IL2CPP 下保留反射类型；需要构造参数时手动传状态实例。任务结束必须检查当前状态仍有效，不能让上一轮重试回调推进新流程。
- **查询**：`ProcedureComponent.cs`、`IProcedureModule.cs`、`ProcedureStateBase.cs`；`Sample.Demo/Scripts/Runtime/Procedure/`，注意是项目示例而非唯一流程实现。

## Scene

- **适用/不适用**：统一记录场景加载状态、防止冲突操作、发布场景事件；不是另一个资源后端。
- **流程**：通过 `GameEntry.Scene.LoadSceneAsync` 指定地址和实际 Single/Additive 模式；在业务需要时用同一地址 UnloadSceneAsync。
- **最小业务模式**：传送前保存必要进度、处理旧场景所有者，再等待新场景加载；持久化 UI/框架根与场景对象分开管理。
- **生命周期/误用**：实际来源由 Resource Helper 决定；默认 Helper 场景需加入 Build Settings。不要混用 SceneManager 与框架造成状态不同步；当前不支持 activateOnLoad:false，不能编造后续激活 API。
- **查询**：`SceneComponent.cs`、`ISceneModule.cs` 与实际 Resource Helper；Demo 场景切换流程。

## Audio

- **适用/不适用**：BGM、SFX、UI 音效、音量与播放控制；设置持久化仍由 Setting 负责。
- **流程**：核对地址和 Helper，选 PlayBgm/PlaySfx/PlayUI 或 Async 入口；音频引用与播放源由模块管理，结束用途时按句柄/播放 API 停止。
- **最小业务模式**：进入业务场景播放 BGM；设置滑块改变 BgmVolume、SfxVolume、UIVolume 并另存 Setting。
- **生命周期/误用**：文件音频、Android/WebGL 本地文件链路使用异步入口；不要另手动归还 Audio 内部持有的 Clip。ClearCache 会停止播放并清缓存，不是每个按钮点击的常规收尾。
- **查询**：`AudioComponent.cs`、`IAudioModule.cs`、`AudioHandle` 和当前 `AudioHelperBase` 实现。

## WebRequest

- **适用/不适用**：HTTP 接口、小型响应和简单文件请求；需要可靠大文件下载、续传、校验时使用 Download，需要长期消息通道时看 Network。
- **流程**：按服务端协议准备 URL、请求体与超时/取消，await GetAsync/PostAsync 后解析响应；序列化、认证和业务错误映射由项目决定。
- **最小业务模式**：公告接口用 GET；只有项目存在远端登录服务时才添加登录请求，离线场景不必建后端。
- **生命周期/误用**：不能把 PostAsync 当成自动序列化对象接口；不要把大响应全放内存，或让关闭界面后的请求继续修改销毁对象。一次性 DownloadFileAsync 不是续传任务管理。
- **查询**：`WebRequestComponent.cs`、`IWebRequestModule.cs`、`DefaultWebRequestHelper`；`Sample.Demo` 的公告加载。

## Download

- **适用/不适用**：大文件、HTTP Range 续传、大小/SHA-256 校验、受限解压；YooAsset 包更新优先用该扩展的更新流程，不重复造下载器。
- **流程**：准备可信任务参数与可写目标，构造 DownloadOptions 和进度处理，调用 DownloadAsync 并检查结果；解压启用后检查条目数、总大小和覆盖策略。
- **最小业务模式**：离线仿真项目下载内容包到 persistentDataPath，校验后解压，使用 LocalFile 的覆盖文件；结束旧资源使用并清相应缓存后才重新加载。
- **生命周期/误用**：同一最终路径不能并发下载；取消/网络失败可保留 .part，不随意删恢复数据。不是上传、系统后台通知或持久化业务版本管理。内置只支持无密码 ZIP，其他格式才考虑扩展。
- **查询**：`DownloadComponent.cs`、`IDownloadModule.cs`、`DownloadOptions.cs` 与 Archive Helper；`Sample.Download`。

## Network

- **适用/不适用**：自定义协议的 TCP/UDP/WebSocket 通道、消息分发；普通 HTTP 接口用 WebRequest，离线业务不强行使用网络。
- **流程**：先匹配服务端协议和 Helper；创建/取得通道，注册消息处理器，再 ConnectAsync/Send；退出所属业务时撤销处理器并按当前通道 API 断开或销毁。
- **最小业务模式**：登录与聊天服务可各用一个具名通道；发送和接收按双方协议处理 Id、字节和失败。
- **生命周期/误用**：默认 TcpNetworkHelper 不是通用任意服务端协议，DefaultNetworkHelper 反而是空实现；内置参考实现不等于弱网、TLS、安全或 WebGL 支持均已生产验证。
- **查询**：`NetworkComponent.cs`、`INetworkModule.cs`、`INetworkChannel`、`INetworkHelper` 和实际协议实现；不从其他框架复制 Send/Connect 参数。

## Advertisement

- **适用/不适用**：统一 Banner/Interstitial/Rewarded 的业务入口；仅存在接口不代表国内平台、微信小游戏或其他真实 SDK 已接入，不能给不支持的平台强行展示广告。
- **流程**：取得 `GameEntry.Advertisement`；项目接入真实 SDK 时实现 `AdvertisementHelperBase`、SetHelper，再按 SDK 规则 Initialize；广告位由项目提供，Load、IsReady、Show、Hide 均按实际实现处理。
- **最小业务模式**：业务请求激励广告，只有收到 `AdvertisementResult.Rewarded` 才发奖；Show 返回 bool 不是奖励依据，Shown/Completed/Skipped 或失败均不发奖。
- **生命周期/误用**：DefaultAdvertisementHelper 的 IsSupported/IsReady 为 false，Show 返回 false 并回调 NotSupported。SetHelper 不自动初始化；不能虚构 SDK 接入、测试广告位或真机验收。
- **查询**：`AdvertisementComponent.cs`、`IAdvertisementModule.cs`、`AdvertisementHelperBase.cs`、`DefaultAdvertisementHelper` 和平台自己的 SDK 文档。

## 基础安全

- **适用/不适用**：ProtectedInt/Long/Float/Bool 提高常规扫描和简单修改成本；Config/Storage/Bundle 的保护按各自模块使用，不承诺专业反破解或服务端权威。
- **流程**：只对确有保护需要的少量高价值字段选用 Protected 类型；需要告警时通过 Event 订阅 MemoryTamperEvent；业务仍自行决定提示、记录或恢复策略。
- **最小业务模式**：积分的运行时值使用 ProtectedInt，持久化快照仍使用明确的数据字段，不假定默认存档序列化器支持 Protected 类型内部布局。
- **生命周期/误用**：字段校验失败读取可返回默认值；扫描不到不能作为全部防护成功证据。不要自动启用全部加密、改密钥或为此增加新的框架 Component。
- **查询**：`Library/RFramework/RFramework/Security/`、Runtime 的安全初始化代码；`Sample.Security`、`Sample.Storage` 和已导入平台密钥仓。

## Debugger 与编辑器工具

- **适用/不适用**：查看模块状态、定位运行问题、辅助构建和资产制作；不是业务逻辑或真实设备验收的替代品。
- **流程/最小业务模式**：先查 Editor/屏幕 Debugger 的相关模块状态与日志，再到模块 API 或资产设置定位；绑定生成器、配置表工具、Prefab 检查和 WebGL 模板按当前菜单与源码操作。
- **生命周期/误用**：不要为了调试重建框架根节点；Inspector 运行时统计是状态读数，不意味着底层任务成功。ReadOnly 属性只限制面板编辑，不提供运行时数据安全。
- **查询**：`Scripts/Runtime/Debugger/`、`Scripts/Editor/`、当前包 README；有独立 Sample 的工具按 [可选扩展](可选扩展.md) 确认可用性。
