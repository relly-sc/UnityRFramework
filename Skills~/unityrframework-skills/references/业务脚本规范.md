# 业务脚本规范

这些规则约束框架的接入、异步和所有权，不规定项目必须使用 MVC、MVP、MVVM、某种目录层级或额外服务层。优先沿用项目已有结构；小需求不必增加抽象。

## 代码放在哪里

- 消费项目业务脚本、场景、Prefab、生成配置类型与项目 link.xml 放项目自己的 Assets 下。不要写入只读 Packages/Library/PackageCache，不要求每个项目复制整个开发仓库。
- Unity 对象生命周期使用 MonoBehaviour，框架管理的 UI/实体行为可分别继承 UIFormLogic/EntityLogic，流程使用 ProcedureStateBase；业务数据快照用适合当前序列化器的纯数据类型。
- 普通按钮脚本、业务模型或小服务不因为用了框架就继承 UnityRFrameworkComponent。它用于项目明确扩展的框架级模块；新增此类模块时核对入口 Prefab 的组件注册方式，沿用独立子物体组织，不随意扩展 GameEntry。
- 命名空间、程序集划分和方法命名沿用项目约定。普通 Sample、Expansion 和 Demo 不新增 asmdef，运行时/编辑器源码默认随宿主编入 Assembly-CSharp / Assembly-CSharp-Editor；命名空间不等于程序集名。仅核心程序集、独立测试程序集和 HybridCLR 通用契约/热更等确需隔离的情况例外。
- 项目自定义 asmdef 按实际类型引用 RFramework.Library、UnityRFramework.Runtime、第三方包等真实程序集；TMP 类型另需 Unity.TextMeshPro。自定义 asmdef 不能反向引用 Assembly-CSharp 中的普通扩展。需要调整时先规划源码归属，不能擅自给扩展/Demo 创建 asmdef 解决引用问题。

## 如何调用模块

- 业务优先使用 GameEntry 的现有入口，不在每个脚本中 new 模块、不建立另一个管理同一职责的单例。不为同一功能同时维护框架 UI/Entity 与私有容器两套状态。
- 模块就绪后才访问；静态字段初始化、ScriptableObject 构造和过早 OnEnable 不应直接取 GameEntry。新脚本的启动位置跟随项目已有初始化流程，不通过大量执行顺序属性掩盖依赖。
- 先查 Controller/Component 是否自动完成某项初始化，再决定是否需要业务调用。Resource.InitializeAsync 应归项目启动链路，不能每个窗口重复初始化。
- Helper 是项目基础设施配置，业务代码消费契约；只有正在实现后端适配或用户明确要求时才更换 Helper，不为一个加载错误同时改所有模块。
- 用扩展实现能力时，确认安装、导入与 asmdef 均满足。using 不会安装包或增加程序集引用。

## 生命周期与清理责任

| 所持有内容 | 何时取得 | 对应收尾 |
| --- | --- | --- |
| Event 订阅/订阅组 | 界面或业务进入有效期 | Unsubscribe 或 EventGroup.Dispose；重入不能叠加订阅。 |
| UGUI/TMP 的业务事件监听 | 当前界面绑定 | 移除自己的同一委托，不 RemoveAllListeners 删除别人或生成器的监听。 |
| Timer 句柄 | 启动延迟或周期任务 | Cancel/CancelTimer；不以 CancelAllTimers 清理单个使用者。 |
| 直接 Resource 加载的引用 | 一次成功加载 | 对应一次精确 UnloadAsset；依赖实例先完成使用和销毁。 |
| 自己 Instantiate 的对象/池实例 | 业务创建或 Spawn | 自己 Destroy 或向原池 Unspawn，不混用两种所有权。 |
| 框架 UI/Entity | Open/Show 或登记场景对象 | 走 Close/Hide/Unregister；不重复释放模块持有的资产。 |
| CancellationTokenSource/异步结果 | 开始当前生命周期的任务 | 离开时取消，按项目任务结束策略释放；迟到结果失效并归还成功取得的资源。 |
| FSM、网络通道等具名/具主的对象 | 业务创建 | 由创建者按当前 API 销毁或关闭，不销毁共享的默认对象。 |

UIFormLogic/EntityLogic 的框架回调与 MonoBehaviour 的 OnEnable/OnDisable 不是同一个契约。按当前 UIForm/Entity 的调用顺序确定订阅与清理位置；使用外部程序集重写 protected internal 成员时核对 C# 可见性，通常使用 protected override，必要初始化调用 base。

## 异步业务

- 可 await 的业务方法返回 Task/Task<T>；异步入口有异常观察、取消和重复点击控制。不要无处理地丢弃 Task，也不把同步框架状态回调改成 async void。
- FSM/Procedure 可保存 Task 并在 OnUpdate 检查完成；项目已使用有完整异常、取消、当前状态/请求版本检查的异步 Task 链路时可沿用，不强制重写成一种模式。
- 每个关键 await 后确认调用者、当前状态和请求代次仍有效，尤其是界面关闭、流程切换、重试和软重启。不仅检查 Unity 对象非 null，也防止上一轮任务写入新一轮业务。
- Unity 对象和多数模块 API 在主线程使用；Event.FireAsync 的线程安全不扩展为所有框架 API 线程安全。不要用 Task.Run 包住 Unity 加载或界面更新。
- 用户取消通常作为正常结束，实际失败保留异常/Reason/Message。不要 catch 后假装成功、默认覆盖存档、重复发奖或无限重试；没有真实业务恢复策略时报告失败。

## 数据、地址与发布

- Setting、Storage、Config 的职责分开。保存使用独立快照；配置行作为共享静态规则消费；语言和音量设置恢复需要业务实际应用。
- location 按当前 Resource Helper 决定；不硬编码开发电脑绝对路径、Sample 包版本、固定服务器或测试广告位。已有项目配置优先，不另塞一套常量替代它。
- 加载的格式与 Helper 匹配，生成行类型/Codec 与产物属于同一套导出契约；不同后端不能仅通过改后缀互相读取。
- 已有 ConfigKey/YooAssetKey 升级复用；Storage 安装级密钥独立。密钥材料不进日志，不擅自更换，不把需要密钥才能读的内容当作密钥加载入口。
- 反射发现的业务 Procedure、字符串 Helper、自定义序列化类型等，按当前序列化器和 IL2CPP 方式检查 Preserve/link.xml、构造函数及泛型约束。程序集名取当前 asmdef，不按文件夹名称猜。
- Editor、Player、平台、启动/关闭/重启和需要的资源归还分别验收。测试数据不要覆盖用户正式存档或发布资产。

## 交付前说明

对新增业务说明实际使用的模块、依赖、需要用户赋值的字段、触发入口、失败处理与清理位置。区分“源码核对”“示例编译”“已运行”；发现框架缺能力时说明当前空实现或需要的项目适配，不把预期功能说成已经实现。
