# 跨模块业务示例

以下是业务类中的方法/成员片段，不是需要安装的新框架 Component。地址、槽位、语言标识和数据由项目提供。调用前确保相应模块就绪；启动读取方法接入项目已有的初始化链路，不直接复制到任意 OnEnable。

公共 using 为 `System`、`System.Threading`、`System.Threading.Tasks`、`RFramework`、`UnityRFramework.Runtime`。异步方法由调用者 await、处理失败并防止重复调用；退出生命周期后不得把返回结果应用到新界面或新流程。

示例设置键是业务示意。接入已有项目时使用该项目启动和设置界面已有的键，不另创建一个与恢复逻辑不同的键。

## 音量保存与恢复

Setting 负责保存，Audio 负责生效；恢复方法应在 Audio 就绪后执行。这是一项统一音量的业务选择，项目若区分三种音量应分别保存。

```csharp
public void RestoreVolume()
{
    float volume = GameEntry.Setting.GetFloat("Audio.Volume", 1f);
    ApplyVolume(volume);
}

public void ChangeVolume(float volume)
{
    ApplyVolume(volume);
    GameEntry.Setting.SetFloat("Audio.Volume", volume);
    GameEntry.Setting.Save();
}

private void ApplyVolume(float volume)
{
    GameEntry.Audio.BgmVolume = volume;
    GameEntry.Audio.SfxVolume = volume;
    GameEntry.Audio.UIVolume = volume;
}
```

## 语言切换后保存

语言须存在于当前项目的导出/收集产物中。初始化时读取相同 Setting 键并等待切换完成；静态文字使用 LocalizedText，动态文字由业务 GetString 刷新。

```csharp
public async Task ChangeLanguageAsync(string language, CancellationToken ct)
{
    var localization = GameEntry.Localization;
    var setting = GameEntry.Setting;
    await localization.SwitchLanguageAsync(language, ct);
    ct.ThrowIfCancellationRequested();
    setting.SetString("Localization.Language", language);
    setting.Save();
}
```

方法假定调用期间模块生命周期仍有效；实际界面须按业务脚本规范检查关闭、请求代次和取消。自定义地址使用当前 SwitchLanguageAsync 显式 location 重载。

## 保存自动槽位与读取

传入的是项目自己的稳定进度快照，不是 MonoBehaviour/场景引用。普通手动保存另用 SaveAsync 和非自动槽位名。

```csharp
public async Task SaveCheckpointAsync<T>(T snapshot, CancellationToken ct)
{
    StorageResult result = await GameEntry.Storage.SaveAutoAsync(snapshot, ct: ct);
    if (!result.Succeeded)
        throw new InvalidOperationException(result.Reason + ": " + result.Message);
}

public async Task<T> ReadCheckpointAsync<T>(CancellationToken ct)
{
    StorageLoadResult<T> result = await GameEntry.Storage.LoadAsync<T>(
        StorageSlotNames.AutoSave, ct: ct);
    if (!result.Succeeded)
        throw new InvalidOperationException(result.Reason + ": " + result.Message);
    if (result.RecoveredFromBackup)
        Log.Warning("自动存档从上一版本备份恢复。");
    return result.Data;
}
```

调用方成功后才更新运行状态；首次无存档与损坏/认证失败应按 Reason 区分，而不是任意失败都自动创建并覆盖旧档。示例不替项目决定重试或迁移策略。

## 预加载配置与打开界面

T 是项目实际生成的行类型，configLocation 与 uiLocation 都须符合当前 Helper；配置加载不应在每次 UI 刷新时重复进行。

```csharp
public async Task<IUIForm> OpenConfiguredPanelAsync<T>(
    string configLocation, string uiLocation, CancellationToken ct) where T : class
{
    var config = GameEntry.Config;
    var ui = GameEntry.UI;
    await config.LoadConfigAsync<T>(configLocation, ct);
    ct.ThrowIfCancellationRequested();
    return await ui.OpenUIFormAsync(
        uiLocation, windowLayer: UILayer.Panel, ct: ct);
}
```

这是“依赖先就绪”的流程示例，不是界面业务模型；字段访问和数据变化仍由项目 UI 脚本处理。界面退出使用 CloseUIForm(uiLocation)，不另手动卸载 UI 模块持有的 Prefab；重入与迟到结果见业务脚本规范。

## 有限生命周期的事件与计时

这些成员属于调用者业务类；在框架就绪并进入有效期后 BeginBindings，离开时 EndBindings。组解绑与计时取消分别由持有者处理，不调用全局清空。

```csharp
private EventGroup bindings;
private RFramework.Timer timeout;

public struct ProgressChanged
{
    public int Value;
}

public void BeginBindings()
{
    EndBindings();
    bindings = GameEntry.Event.CreateGroup();
    bindings.Subscribe<ProgressChanged>(OnProgressChanged);
    timeout = RFramework.Timer.CreateOnce(
        3f, () => Log.Info("当前业务等待结束。"), ignorTimescale: true);
    GameEntry.Timer.RegisterTimer(timeout);
}

public void EndBindings()
{
    timeout?.Cancel();
    timeout = null;
    bindings?.Dispose();
    bindings = null;
}

private void OnProgressChanged(ProgressChanged message)
{
    Log.Info("当前进度：{0}", message.Value);
}

public void NotifyProgress(int value)
{
    GameEntry.Event.Fire(new ProgressChanged { Value = value });
}
```

## 项目流程组合

下面是职责顺序，不是额外 API：

- 设置页：等待模块就绪 → 读取 Setting → 应用 Audio/Localization → 交互改变 → 成功后保存 → 关闭解绑。
- 读档进入场景：选择业务槽位 → LoadAsync 检查结果 → 加载必要 Config/场景/实体 → 应用快照 → 打开 HUD。
- 换图自动保存：选择实际保存时机 → 形成稳定快照 → SaveAutoAsync 检查结果 → 清理旧场景业务 → Scene 加载 → 恢复新场景状态。
- 资源更新启动：核对实际 YooAsset Package/模式/服务器 → 按扩展流程完成初始化与版本/清单/下载 → 准备配置和语言 → 进入业务；不能用通用 Download 再重复管理同一包。
- 激励广告：检查真实 SDK Helper → 初始化并加载广告位 → 允许 Show → 只在 Rewarded 回调且当前业务请求仍有效时发奖；当前默认 Helper 没有真实广告。

已有业务流程优先，不把这些组合强制实现成某个架构，也不把仿真项目改造成需要账号、广告和服务器的游戏。
