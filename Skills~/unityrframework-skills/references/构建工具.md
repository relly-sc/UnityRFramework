# 构建工具参考

## 适用与不适用

用于当前项目的 Player、配置导出、资源包、热更新和发布流水线。不是运行时业务模块，也不把所有可选插件当作必装依赖；普通业务编码不应顺便改 Player Settings、服务器、密钥或构建 Profile。

菜单为 `UnityRFramework/构建工具`。Profile 通常位于项目 `Assets/BuildProfiles/`，不写入只读包。详细行为查当前 README 的“编辑器构建工具”和 `Scripts/Editor/BuildPipeline/`。

## 选择本次构建范围

| Recipe | 何时使用 |
| --- | --- |
| Player | 只构建客户端或更新 Player/AOT 基线，不发布资源和热更代码。 |
| Assets | 需要导出 Config 并构建资源，不改客户端代码基线。 |
| HotUpdate | 在可用 Player 基线上更新热更代码与资源，不构建 Player。 |
| Release | 需要当前已启用步骤的完整发布链路，首次接入或基线变化时尤其应核对完整准备流程。 |

Flavor 是用途和推荐调试参数，不自动切换 Mono/IL2CPP。实际平台、后端、启用场景、步骤及输出都取 Profile 当前值；按钮可能覆盖保存的 Recipe，不能仅看下拉框推断任务。

## 正常流程与最小业务模式

1. 核对当前目标平台、Profile、有效且启用的场景、项目/场景中的 Component 与实际 Helper，以及已注册的构建步骤。
2. 选择需要的 Recipe 与步骤。Config 来源按已实现且项目已导入的 CSV/Excel 工具选择；输出内容格式与 Runtime Helper、Codec、保护设置和资源收集地址对应。
3. 处理本次校验错误，执行用户要求的构建。资源服务器应发布本次目标平台对应的版本、清单、Bundle 和热更产物，不把旧服务器内容误判为客户端代码缺陷。
4. 用 build-report.json 核对任务、版本、平台、失败步骤及产物；需要验证运行时行为时再运行目标 Player，不以构建按钮显示成功代替运行验证。

最小模式：核心 Config 项目构建 Player 时确认导出产物可被当前 Resource Helper 加载；导入 YooAsset 后再增加其资源步骤；有 HybridCLR 才执行相应代码准备，有 Obfuz 才加混淆，不默认启用所有步骤。

## 生命周期与常见误用

- 构建占用当前 Unity Editor，按单编辑器串行操作，不并发构建，也不强制中断 Player 编译；不承诺无感后台、多进程或窗口重开能跳过官方阻塞进度。
- Profile 是项目配置事实源；不要把“最近构建”当当前未执行任务的版本，也不把资源报告路径当 Player 输出路径。
- ConfigKey、YooAssetKey 和 Storage 的安装级密钥分开。构建或小版本更新复用已有内容密钥，不自动重生，也不把认证失败通过删除 JSON、关闭加密或删除用户数据“修复”。
- HybridCLR AOT 基线绑定目标平台与实际 Player。Obfuz 联合流程核对扩展 README 与当前步骤实现，不无条件运行普通 HybridCLR Generate/All；增量热更不能混用旧 AOT 元数据。
- Editor 模拟加载、Mono/IL2CPP 编译、Player 启动和真机验收分别报告。其他平台成功不能证明本平台成功。

## API 与示例查询

核心查 BuildProfile、BuildPipelineRunner、BuildStepRegistry 和实际配置资产类型；可选步骤查当前导入扩展的 Scripts/Editor/BuildPipeline。完整资源更新示例看 Expansion.YooAsset.Demo，代码更新看 Expansion.HybridCLR.Demo；以消费项目可访问的版本目录为准。
