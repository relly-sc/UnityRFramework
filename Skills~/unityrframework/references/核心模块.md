# 核心模块参考

这是选型和边界提示。实际签名以当前核心包 `README.md`、`Scripts/Runtime/GameEntry.cs`、对应 `Component` 和 `I*Module` 为准。

| 需求 | 使用入口 | 先核对 |
| --- | --- | --- |
| 少量音量、语言、分辨率等设置 | `GameEntry.Setting` | 默认 PlayerPrefs；写入后 `Save()`；读取后业务自行应用；不存敏感数据。 |
| 玩家进度、多槽位存档 | `GameEntry.Storage` | `SaveAsync` / `LoadAsync` 的结果及选项；加密密钥属于安装级，不等于跨设备同步。 |
| 自动存档 | `GameEntry.Storage.SaveAutoAsync(data)` | 固定槽位 `StorageSlotNames.AutoSave`；业务在选择、结算、换图等时机调用；普通 `SaveAsync` 不得覆盖该槽位。 |
| 静态数据表 | `GameEntry.Config` | CSV/Excel 是导出来源，运行时 JSON/二进制格式、Helper 和资源路径必须匹配。 |
| 多语言 | `GameEntry.Localization` | 静态 UGUI/TMP 文本可用 `LocalizedText`；动态文本由业务脚本取值；资源仍由 Resource Helper 加载。 |
| Prefab、音频、场景等资源 | `GameEntry.Resource` | 成功加载的业务资源要精确 `UnloadAsset`；地址随 Helper 改变。 |
| 窗口与场景 UI | `GameEntry.UI` | 普通 Prefab、独立 Canvas、场景已有 UI 的所有权不同；查看 README 的 UI 章节。 |
| BGM 与音效 | `GameEntry.Audio` | 音频资源通过 Resource 加载；平台文件音频可能需要异步 API。 |
| HTTP、小文件请求 | `GameEntry.WebRequest` | 大文件断点续传使用 `GameEntry.Download`，不要用普通请求重复实现。 |
| 运行时广告入口 | `GameEntry.Advertisement` | 已实现统一接口和默认空 Helper；具体广告平台 SDK 适配尚未实现，详见下方广告模块说明。 |

其他 `GameEntry` 入口包括 `Framework`、`Event`、`Pool`、`Timer`、`Fsm`、`Procedure`、`Entity`、`Scene`、`Network`。日志使用 `Log.Info/Warning/Error`。先在核心 README 的同名章节找现有示例，再核对源码；不要仅凭其他框架的同名 API 推断参数。

## 项目接入与生命周期

- 启动场景通过框架的 `Prefabs/UnityRFramework.prefab` 安装模块，先检查已有实例，避免添加第二个框架根节点。模块组件由框架启动时登记，业务应在框架就绪后访问 `GameEntry`。
- 命名空间为 `RFramework` 与 `UnityRFramework.Runtime`。业务使用自定义 asmdef 时，按所用类型引用 `RFramework.Library` 和 `UnityRFramework.Runtime`；需要 TMP 或 Expansion 类型时另核对它们的实际程序集引用，不能仅添加 `using` 解决缺失引用。
- 以字符串类型名配置的自定义 Helper、反射发现的业务 Procedure 等，需要在 IL2CPP 构建中保留对应类型和构造函数。参考核心 README 的裁剪说明，在项目自己的 `link.xml` 或类型上配置保留，不修改只读包。
- FSM/Procedure 生命周期是同步 `void` 回调。状态内的资源、网络等异步任务应在 `OnUpdate` 检查完成及当前状态仍有效后再切换，不能把回调改成 `async void`。

## 广告模块当前能力

- 框架入口 Prefab 的 `Advertisement` 子物体挂载 `AdvertisementComponent`。业务在框架就绪后通过 `GameEntry.Advertisement` 获取；该入口采用与其他核心模块一致的惰性缓存，框架停止或软重启时清空缓存。
- 核心提供 `Banner`、`Interstitial`、`Rewarded` 三种广告类型，以及 `Initialize`、`Load`、`IsReady`、`Show`、`Hide` 统一入口。
- 当前随框架提供的实现只有 `DefaultAdvertisementHelper`。它初始化后仍然 `IsSupported == false`、`IsReady == false`；`Show` 返回 `false`，并回调 `NotSupported`，不会展示广告。
- 当前没有已实现的 Android 国内广告平台、微信小游戏或其他平台的真实 SDK 适配。不要把统一接口存在解释为这些平台已可直接展示广告。
- 项目接入 SDK 时实现 `AdvertisementHelperBase`，通过组件的 Helper 类型名或 `SetHelper` 安装，并按 SDK 的初始化流程调用 `Initialize`。通过 `SetHelper` 替换 Helper 不会自动初始化新的 Helper。广告位编号由项目提供，空编号会被拒绝。
- `Show` 的布尔返回值不能作为发奖依据；激励奖励仅在确认 `AdvertisementResult.Rewarded` 回调时发放。`Shown`、`Completed`、`Skipped` 和失败结果均不能被 AI 当作奖励确认。

核对源码位置：`Scripts/Runtime/Advertisement/` 和 `Library/RFramework/RFramework/Advertisement/`。广告接口的测试结果不代表任何真实 SDK、设备展示或激励回调已经验收。

## 常见区分

- `Setting` 是少量非敏感键值；`Storage` 是玩家存档；`Config` 是发布的静态配置。不要互相代替。
- `Framework` 的通用 JSON Helper 不决定 Config 或 Localization 的内容格式。
- UI 与 Entity 的 Helper 只负责实例化；实际资源加载归 Resource 模块。业务直接加载的资源由业务归还。
- `Event.FireAsync` 可跨线程入队，分发发生在主线程；不要假设其他模块 API 也可任意跨线程调用。
- 内置 Network Helper 是基础实现，不等于已通过项目协议、弱网和平台安全验收。
- 运行时换语言、换场景、热更代码都具有不同生命周期；不要用框架软重启代替完整进程重启来激活新 DLL。
