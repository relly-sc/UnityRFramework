# 构建工具参考

菜单 `UnityRFramework/构建工具` 打开窗口。Profile 是项目资产，通常位于 `Assets/BuildProfiles/`；构建工具不会把业务 Profile 写入只读包。当前详细规则见核心包 README 的“编辑器构建工具”和 `Scripts/Editor/BuildPipeline/`。

## 判断本次要做什么

| Recipe | 范围 |
| --- | --- |
| `Player` | 构建 Player，不发布资源或热更代码。 |
| `Assets` | 导出 Config 并构建资源包，不构建 Player。 |
| `HotUpdate` | 准备热更代码并构建资源包，不构建 Player。 |
| `Release` | 当前已启用步骤的一条完整构建流水线。 |

`Flavor` 是用途及推荐调试参数，不自动切换 Mono/IL2CPP；脚本后端、平台、构建场景和步骤启用状态都需从 Profile 实际值读取。按钮可能覆盖 Profile 保存的 Recipe，不能仅看下拉框推断本次任务。

## AI 操作前检查

1. 识别当前目标平台、场景列表、Profile、已注册的构建步骤和 Inspector/第三方设置；先定位校验错误，再改最小必要处。
2. `Config`、YooAsset、HybridCLR、Obfuz 分别有独立前置条件。未导入对应扩展时不应启用其步骤；不要为了“完整”默认安装全部插件。
3. 加密 Config 的内容格式、导出步骤、运行时 Config Helper 和密钥文件须一致。YooAsset Bundle 加密另用独立密钥，不与 ConfigKey 混用。
4. HybridCLR 的 AOT 基线绑定目标平台与 Player；只更新热更代码时遵循扩展 README 的增量流程，不能无条件重做 `Generate/All` 或混用旧基线。
5. 构建会修改项目级设置并占用 Unity Editor。不要并发运行两个构建，也不要强制中断 Player 编译。失败时读取当前任务、校验结果和 `build-report.json`，不要从“最近构建”推断正在执行的版本。

只有实际运行过对应平台构建及 Player，才能报告该平台验收通过。其他平台的成功不能代替目标平台验证。
